# 概念解析
## 分支与合并的解释
分支：分支可以理解为代码的一条独立开发线路。我们可以在不改动main主分支代码的前提下，在新分支上做修改、调试，不会破坏主仓库原本的内容，相当于尝试代码的预定路线，在分支上的尝试尝试不会影响原代码

合并：合并就是把其他分支上完成的改动，合并回main主分支，把分支里面修改的内容整合给原代码
# 贪吃蛇解析（已经提前给ai看过考核的整体要求，给ai留下对应记忆方便后续使用）
## 过程
### 阶段一
#### 编写
    提示词：以html格式设计一个贪吃蛇小游戏（撞墙和撞到自己视为死亡，食物不可以生成在自己身上），要求能够手动游玩，界面整洁，能够计算得分、最高纪录，有重置按钮方便我多次进行游玩，在代码中添加详细的说明，简单解释代码分区和逻辑
    结果：ai给出了初版代码，能初步满足要求
#### 验证
    右键贪吃蛇文件通过vscode的终端浏览器尝试本地运行，尝试游玩后发现对于人来说100毫秒的每次运动间隔太快了，我将其改成150，更适应新手游玩
### 阶段二
#### 便携
    提示词：加入ai自动操作模式，独立出一个按钮方便随时切换ai游玩，ai需满足不撞墙、不撞自己、至少连续吃完15个食物不死的要求，并指引我更改初版代码
    结果：ai给出了一段代码，指导我将其插入初版代码，重新对ui进行排布，并成功完成要求
#### 验证    
    右键贪吃蛇文件通过vscode的终端浏览器尝试本地运行，ai成功做到不触犯死亡规则的前提下吃到15个以上的食物
## 原理拆分
### 贪吃蛇中食物为什么不会生成在自己身上?
    代码随机生成了个坐标，检测坐标是否在蛇身上。如果在，则递归重新生成坐标。如果不在，则在坐标位置生成食物
### ai操控下蛇为什么不会撞墙或身子?  
    代码生成一片画布并将画布分割成x*y的网格，提前预设出四个前进方向（上下左右），判断蛇头的下一个坐标是否处于0到x-1或y-1之间&是否是自己身上的节点，不满足要求则舍弃这个前进方向，最终通过曼哈顿距离（两点距离中横竖方向的格子数之和）比较最优前进方向，若曼哈顿距离相等则按右上左下的顺序进行选择
### 蛇的寻路逻辑是什么？
    在保证自身安全（不撞墙和身子）的前提下通过安全路径选出最小曼哈顿距离的走法
